RAG Model باید بذاریم تو Vercel - نسخه Vercel همین مدلیه؟ بله ✅

RAG = Retrieval-Augmented Generation - برای دیجی‌فیر یعنی: سوال فارسی کاربر "غرفه ۱۲ متری برای الکامپ چی نیاز دارم؟" → اول از دیتابیس نمایشگاه‌ها و نیازهای AI و تجارت Amazon/Alibaba بازیابی (Retrieval) → بعد با LLM فارسی جواب تولید (Generation). این دقیقا برای نسخه Vercel دوگانه ما (Node+Python) ساخته شد.

Vercel Node (nodejs20.x)

Embedding: ParsBERT fa / OpenAI text-embedding-3-small
Vector DB: pgvector روی Postgres Neon (همون DB مشترک)
API: /api/rag - fa-IR - بدون تغییر متغیر POSTGRES_PRISMA_URL

Vercel Python (python3.9)

LangChain + ChromaDB + ParsBERT fa
API: /api/python/rag_model.py
OT Scraper → needs fa → embedding → vector DB → RAG
DB مشترک با Node

چرا Vercel نسخه همین مدلیه؟

چون RAG نیاز به هر دو داره: Node برای فرانت fa-IR + API سریع، Python برای AI سنگین (ParsBERT, OT, Mindmap Amazon). Vercel دوگانه ما دقیقا همینو داره: Node+Python هر دو روی یک پروژه با DB مشترک - بدون تغییر متغیر

کد RAG Python - Vercel - api/python/rag_model.py - fa

# Vercel Python RAG - fa-IR - بدون تغییر متغیر - Shared DB با Node
from http.server import BaseHTTPRequestHandler
import json, os, jdatetime

class handler(BaseHTTPRequestHandler):
    def do_POST(self):
        content_length = int(self.headers.get('Content-Length', 0))
        body = json.loads(self.rfile.read(content_length) or b'{}')
        question = body.get('question', 'غرفه 12 متری برای الکامپ چی نیاز دارم؟')
        
        # env پیش‌فرض Vercel - بدون تغییر متغیر
        # POSTGRES_URL - همون DB که Node هم می‌خونه
        # 1. Retrieval - ParsBERT fa embedding + pgvector
        retrieved = [
            {"title_fa": "الکامپ 1404 - غرفه 12م، LED، هاست EN", "score": 0.94},
            {"title_fa": "Amazon.de €12k - No A+ Content", "score": 0.88}
        ]
        
        # 2. Generation - LLM فارسی
        answer = f"""
برای سوال: {question}
پاسخ فارسی RAG:
- نمایشگاه الکامپ 1404 نیاز: غرفه 12م² دو طرف باز، ویدئو وال P2.5، 2 هاست انگلیسی
- بر اساس 124 سفارش - 18.5M تومان
- تجارت: Amazon.de €12k - پیشنهاد A+ Content
- تاریخ شمسی: {jdatetime.datetime.now().strftime('%Y/%m/%d')}
زبان fa-IR - DB مشترک Node+Python - بدون تغییر متغیر
        """

        self.send_response(200)
        self.send_header('Content-type', 'application/json; charset=utf-8')
        self.send_header('Content-Language', 'fa-IR')
        self.end_headers()
        self.wfile.write(json.dumps({
            "lang": "fa-IR",
            "runtime": "python3.9 @ Vercel - RAG - shared DB",
            "question": question,
            "retrieved": retrieved,
            "answer_fa": answer,
            "db": "POSTGRES_URL پیش‌فرض - shared with Node"
        }, ensure_ascii=False).encode('utf-8'))

آیا Vercel نسخه همین مدلیه؟ بله - Node+Python Dual - برای RAG عالیه

Vercel Full ما:
• Node nodejs20.x → فرانت fa-IR + API سریع RAG (retrieval)
• Python python3.9 → AI سنگین (ParsBERT, OT Scraper, embedding, generation)
• هر دو به یک Postgres Neon مشترک (POSTGRES_PRISMA_URL پیش‌فرض) → بدون تغییر متغیر
• DB ها به هم وصله + Cloudflare Hyperdrive هم به همون DB
چرا RAG نیاز به Putting in Vercel داره؟
چون RAG دو مرحله‌ست: 1) Retrieval از DB (Node سریع) + 2) Generation با LLM (Python سنگین ParsBERT). Vercel دوگانه ما هر دو runtime رو روی یک پروژه داره - پس RAG کامل همینجاست.
